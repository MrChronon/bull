# Участие в BULL

[English](CONTRIBUTING.md) · Русский

BULL — Benchmark Lab принимает предложения и небольшие проверяемые изменения
на русском и английском. Начните с проблемы пользователя и воспроизводимого примера.

## Каналы обратной связи

- Discussions — вопросы, методика, идеи, taxonomy и ограничения scorers.
- Benchmark feedback — ложный успех/отказ, неоднозначное задание или проблема сопоставимости.
- Bug report — воспроизводимый сбой приложения, установки, соединения или отчёта.
- Feature request — конкретный сценарий, ограничения и критерий приёмки.
- Pull request — согласованное либо независимо проверяемое изменение.

Сначала проверьте существующие обсуждения. Уязвимости не раскрывайте публично:
используйте [политику безопасности](SECURITY.md).

## Что приложить к Issue

1. Версию BULL и набора, case ID/scorer для дефектов оценки.
2. Windows, Python, backend и краткие шаги воспроизведения.
3. Ожидаемый и фактический результат отдельно.
4. Минимальный обезличенный пример; подтверждение права его публиковать.

Не прикладывайте ключи, токены, адреса, имена пользователей, личные пути,
connection store, приватные prompts/ответы и необработанные логи. Share-safe
JSON тоже требует проверки названий моделей и других разрешённых метаданных.

## Правила изменений

Прочитайте целиком [AGENTS.md](AGENTS.md), [AI_CONTEXT](Docs/AI_CONTEXT.yaml)
и [руководство](Docs/USER_GUIDE.md).

- Один PR — небольшое проверяемое изменение, без big-bang rewrite.
- До извлечения модуля сохраните поведение regression tests.
- Не объединяйте изменение prompt, scorer и runtime pipeline.
- Native-метрики модели и recovery-метрики клиента остаются раздельными.
- Укажите влияние на schemas, старые результаты и совместимость.
- Обновляйте парные `Docs/en` и `Docs/ru` вместе с AI_CONTEXT.
- Не добавляйте Runtime, Chats, Benchmarks, Exports, Workspace, модели и секреты.

На Windows выполните:

```powershell
.\Run-Tests.ps1
.\Test-Public-Release.ps1 -AuditReleaseCandidatesOnly
```

Для упаковки и релиза нужен также `Build-Release.ps1` с новой папкой вывода.
См. [инструкцию релиза](Docs/ru/RELEASING.md) и
[незакрытую приёмку](Docs/RELEASE_READINESS.md). Автотесты не заменяют live-проверку.

## Наборы и PR

Набор — данные, не plug-in. Он объявляет версию, совместимость, лицензию,
provenance и hashes; исходники автора и проверочные ответы могут быть приватными.
Читайте [инструкцию автора](Docs/ru/PACK_AUTHOR_LLM.md) и
[мастерскую](Docs/ru/AUTHOR_WORKSHOP.md). Не меняйте установленную версию на месте
и не пересчитывайте исторические результаты молча.

В PR опишите цель, альтернативы, безопасность, совместимость, выполненные
автоматические/ручные проверки и точный список изменений prompt/scorer/runtime.
Соблюдайте [правила сообщества](CODE_OF_CONDUCT_RU.md).

## Права

Проект распространяется по [MIT](LICENSE). Отправляя PR, подтвердите право
передать работу на этих условиях. Для стороннего кода и данных нужны явные
источник и совместимая лицензия; модели и внешние наборы сохраняют свои лицензии.
