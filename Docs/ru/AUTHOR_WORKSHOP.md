# Мастерская автора

[English version](../en/AUTHOR_WORKSHOP.md)

Доступна в BULL v0.29.0.1 Pack Library.
Модель, backend и сторонние Python-пакеты не нужны.

## Создать, отредактировать, проверить, собрать

Путь: **Главная → Настройки тестов → Мастерская автора**.

1. **Создать редактируемый пример**. Введите уникальный ID строчными латинскими
   буквами, например `my_tasks`. Пример использует язык интерфейса и синтетические данные.
2. **Открыть папку выбранной копии**. Редактируйте UTF-8 файлы текстовым редактором.
   Можно выбрать уже подготовленную папку исходников по пути.
3. **Проверить исходники и примеры ответов**. Зелёный PASS — балл и проваленные
   критерии совпали с ожиданиями. Красный FAIL — расхождение. Исправьте эталоны,
   правила или ожидания примеров перед сборкой. Если исходники изменились после
   preview, повторите проверку перед подтверждением сборки.
4. **Собрать ZIP**. Прочитайте предупреждение о содержимом архива и подтвердите.
5. В библиотеке выберите **Импортировать свой ZIP**, затем нужные тесты.

Создание копии или ZIP не устанавливает, не выбирает, не запускает и не публикует
набор. Пример имеет статус `experimental` и видимость `private`; он не заявляет
прав на распространение добавленных вами данных. Укажите реальные права до передачи.

## Файлы и хранение

Библиотека Windows: `%LOCALAPPDATA%\BULL\BenchmarkPacks`.
Копии находятся в `Workspaces/<id>-<unique_id>/`, архивы —
в `PackExports/<id>@<version>.zip`. Они сохраняются при обновлении приложения.
Это пользовательские файлы, которые не входят в релиз BULL. Ненужные копии и
экспортированные ZIP удаляются вручную после сохранения нужных данных.

```text
author.json          метаданные набора и явный список заданий
Tasks/ticket.yaml    отдельный файл задачи с критериями
Tasks/poem.txt       необязательная задача без автоматического балла
fixtures.json        ожидаемые успешные и ошибочные ответы
README.md            назначение, покрытие, эталоны и ограничения
LICENSE.txt          реальные условия распространения набора и данных
```

Принимаются только перечисленные исходники. Личные заметки, секреты, результаты
и посторонние файлы храните вне рабочей папки. ZIP намеренно сохраняет исходники
в `Source/`, включая prompts и ответы fixtures. Это не share-safe отчёт.
Проверяйте содержимое перед передачей другим людям.

## Контракт author.json

Это схема авторских исходников, не замена runnable manifest v1. Сборщик создаёт
manifest, скомпилированные cases, gold snapshots и lock.

```json
{
  "schema": "bull-pack-workspace",
  "schema_version": 1,
  "id": "my_tasks",
  "version": "1.0.0",
  "title": "Извлечение полей заявки",
  "description": "Синтетические поля, не смысловая оценка обращения",
  "status": "experimental",
  "visibility": "private",
  "minimum_engine_version": "0.29.0.1",
  "license": {"id": "LicenseRef-Private-Review", "name": "Частный проект"},
  "provenance": {"source": "Синтетические записи"},
  "tasks": [
    {"file": "Tasks/ticket.yaml", "category": "field_extraction", "case_version": 1}
  ]
}
```

Неизвестные поля и повторные JSON-ключи запрещены. ID — 3–64 символа из строчных
латинских букв, цифр и `_`, первый символ — буква. Версия содержит три или четыре
числовых компонента. Статус — `experimental` или `candidate`, не самостоятельно
присвоенный сертификат `stable`. Видимость — `private` или `public`; `public`
ничего не загружает в Интернет. В provenance обязательны `source` и необязателен
`author`. Не включайте ключи, адреса подключений и приватные пути.
Согласуйте license ID/name и `LICENSE.txt`. MIT BULL не лицензирует ваши данные автоматически.

Каждое задание имеет `file`, `category` и целый `case_version` (1–1000000).
Файл лежит непосредственно в `Tasks/`. Категория — идентификатор из строчных
латинских букв, цифр и `_`, 2–64 символа, первый — буква. YAML содержит свои
ID/title/description/language/prompt и критерии; не дублируйте эти поля в описателе.
Для `.txt` описатель дополнительно требует `id`, `title`, `description` и
`language` (`en`, `ru`, `auto`). Текст — только prompt, без автоматического балла.
В одном наборе допустимы разные области и языковые варианты; ID задач уникальны.

Необязательный `parameters` поддерживает только:

| Поле | Значение |
| --- | --- |
| `primary_predict`, `recovery_predict` | целое 1–32768 |
| `think_override` | boolean |
| `benchmark_defaults.ctx` | целое 512–262144 |
| `benchmark_defaults.num_predict` | целое 1–32768; совпадает с `primary_predict`, если заданы оба |
| `benchmark_defaults.num_thread` | целое 1–256 |
| `benchmark_defaults.temperature` | число 0–2 |
| `benchmark_defaults.top_p`, `min_p` | число 0–1 |
| `benchmark_defaults.top_k` | целое 0–1000 |
| `benchmark_defaults.repeat_penalty` | число 0–2 |

Это прежние правила defaults/overrides runtime, не новые жёсткие ограничения.
Именованные профили прогона и явные overrides могут заменить defaults.
`think_override` — явная политика задачи. План показывает разрешённые настройки;
sampling режима профиля модели остаётся унаследованным и не отправляется в API.
Настройки чата не меняются. Используйте `ctx`, не `num_ctx`; неподдерживаемые поля запрещены.

## YAML-критерии и проверочные ответы

Точную схему задачи, шесть типов критериев, веса с суммой 100, допуски и
critical cap см. в [инструкции для LLM-автора](PACK_AUTHOR_LLM.md).
YAML `version: 1` — версия схемы исходника, отдельная от `case_version`.

`fixtures.json`: schema `bull-author-fixtures`, `schema_version: 1`, список `cases`.
Каждая оцениваемая задача встречается один раз со своим ID и 2–64 объектами ответа:

```json
{
  "id": "invented_confirmation",
  "kind": "negative",
  "answer": "BENCHMARK_RESULT\n{\"result\":{\"id\":\"B-104\",\"quantity\":3,\"confirmed\":true}}",
  "expected_score": 0.59,
  "failed_checks": ["ticket_confirmation"]
}
```

Ответ содержит ровно `id`, `kind`, `answer`, `expected_score`, `failed_checks`.
Балл — конечное число 0–1, не проценты. `positive` ожидает 1 и отсутствие провалов;
`negative` — меньше 1 и неповторяющиеся ID критериев. Каждая оцениваемая задача
требует минимум один успешный ответ. Среди ошибочных примеров каждый критерий
должен провалиться хотя бы раз. Один пример может проверять несколько провалов.
Неоцениваемые `.txt` здесь не перечисляются; полностью ручной набор использует
`"cases": []`. Ручная оценка не превращается в численный score.

Пример содержит правильный ответ, выдуманное подтверждение (cap 59%) и лишний
текст после JSON (провал всех JSON-критериев). Добавляйте также отсутствующие поля,
ошибочные типы, границы допусков и предметные ошибки. Совпадение fixtures проверяет
поведение правил, не истинность эталона, репрезентативность или профессиональную
безопасность. Допущения, расчёты, единицы, права и смысловые ограничения проверяет человек.

## Обновление, ограничения и команды

**Копировать авторский набор в новую версию** требует `ID@версия` и другую явную
версию. Перед копированием проверяются hashes исходников и соответствие собранному
набору. Установленная версия, активный выбор и прежние прогоны остаются неизменными.
Старые native-наборы без workshop `Source/` автоматически не конвертируются:
запросите исходники у автора или используйте его maintainer tool. Не подменяйте
native scorer keyword-правилами ради видимости совместимости.

ZIP воспроизводим и не перезаписывает существующий файл. Выберите новую версию
или имя выхода. При изменении prompt или критерия также задайте новую подходящую
`case_version`. Сам номер версии не доказывает совместимость.

Ограничения: 1000 задач; 256 KiB на исходник задачи/документ; prompt до 50 000
символов; 1–20 критериев; author/fixtures/compiled JSON до 8 MiB; архив 64 MiB;
распакованный набор 128 MiB; 4096 entries с учётом сохранённых исходников.
Эти бюджеты могут ограничить набор раньше числа задач. Усечения на старом пределе
100 задач нет. Установка дополнительно проверяет свои bounds и hashes.
Код автора, shell, regex, YAML tags и imports не исполняются.

Альтернатива через CLI из папки приложения:

```powershell
python Tools/build_author_pack.py create my_tasks --language ru
python Tools/build_author_pack.py validate "PATH_TO_WORKSPACE"
python Tools/build_author_pack.py build "PATH_TO_WORKSPACE" --output "PATH_TO_OUTPUT.zip"
python Tools/build_author_pack.py copy my_tasks 1.0.0 1.1.0
```

`validate` возвращает exit 1 при неверных исходниках или несовпадении fixtures.
`build` также проверяет runnable registry-контракт и ZIP preflight, не принимает
выходной ZIP внутри исходной папки. `--library-root` перед подкомандой позволяет
указать отдельное хранилище для изолированных проверок. Команды не публикуют и не устанавливают набор.
