# Безопасность и приватность

## Границы доверия

BULL — локальное приложение, а не облачный сервис. Оно доверяет выбранному
пользователем окружению Python/PowerShell, inference engine, установленным моделям
и явно переданным файлам. Ответ модели, импортированное подключение, benchmark
pack, сгенерированный код и сторонняя модель считаются недоверенными данными.

## Безопасные настройки по умолчанию

- чистый build запускается в локальном режиме и не знает частного сервера;
- удалённый inference использует pinned SSH tunnel и loopback-only API;
- байты приватного ключа не копируются в профиль подключения;
- HTTP redirects блокируются до передачи authorization header;
- внешний plain HTTP по умолчанию запрещён;
- сбой связи не переключает выбранный backend без решения пользователя;
- benchmark artifacts записываются атомарно, resume сохраняет готовые runs.

## Секреты и приватное состояние

Нельзя добавлять в Git или публиковать:

- `Runtime`, `Chats`, `Benchmarks`, `Exports` и `Workspace`;
- `client_debug.log` и диагностические логи;
- приватные SSH-ключи, пароли, tokens, API keys и `.env`;
- личные endpoints, usernames, router exports и connection JSON реальной инфраструктуры;
- raw prompts, responses, attachments и evidence без ручной проверки.

Public release gate проверяет manifest, имена, extensions, содержимое, archives,
пути, defaults подключения и итоговый ZIP. Он не заменяет ручную проверку данных,
которые пользователь решит опубликовать позднее.

## Подлинность SSH

Проверяйте fingerprint сервера через независимый канал. BULL закрепляет host key
для каждого подключения. Несовпадение требует остановки, а не игнорирования.
Используйте отдельный ключ и непривилегированную учётную запись. Постоянная запись
хранит путь к ключу, но не его байты. Удаление записи не отзывает доступ на сервере.

## Доступ из Интернета

Предпочтителен VPN. Если требуется direct SSH, перенаправьте один внешний TCP-порт
на Windows OpenSSH, а Ollama/llama.cpp оставьте на loopback. Не используйте DMZ и
UPnP. Перед автономной работой настройте обновления ОС, вход только по ключу,
firewall и контроль логов.

## Ответ модели и tools

Ответ LLM — данные, а не доверенная команда. Сгенерированный код и chat tools
работают с правами текущего пользователя и не являются безопасной песочницей.
Недоверенный код запускайте в disposable VM без учётных данных и сети. Любое
разрушительное или внешнее действие требует проверки.

Пользовательские YAML-тесты и публичные benchmark packs являются data-only.
Неподдерживаемые конструкции отклоняются и не исполняются как Python. Для legacy
CODE-style evaluation по-прежнему нужна изолированная среда.

## Отчёты

Автономный HTML не загружает внешние ресурсы, но может содержать имена моделей,
prompts, ответы, локальные пути и детали эксперимента. Share-safe output уменьшает
риск, но не является гарантией анонимности.

## Реакция на инцидент

Если раскрыт ключ, token или endpoint:

1. отзовите или замените его в authoritative service;
2. удалите публичный SSH-ключ из `authorized_keys`, если затронут SSH;
3. проверьте логи сервера и роутера;
4. удалите секрет из рабочих копий и истории Git, если требуется;
5. соберите релиз из чистого checkout и запустите public release gate;
6. опишите затронутый релиз и исправление, не публикуя сам секрет.

Уязвимость следует сообщать приватно, если публичное раскрытие увеличит риск.
