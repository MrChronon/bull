# Разработка и выпуск релиза

## Архитектура

BULL сохраняет три продуктовые границы:

- Client: чат, lifecycle сессии и явный импорт tested profile;
- Benchmark Lab: каталог, план запуска, scoring, checkpoint/resume и отчёты;
- `Shared/bull_llm`: backend adapters, profiles, schemas, evaluation contracts,
  telemetry, evidence, storage, compatibility и presentation helpers.

Публичный Python namespace — `bull_llm`. Исторические schemas артефактов читаются
через compatibility adapters и никогда не переписываются молча.

## Дорожная карта разработки

BULL v0.29.0.1 Pack Library завершает PK1.0–PK1.5. Движок использует одну
явно выбранную версию набора; базовые ZIP не являются запасным каталогом.
Общая библиотека, мастерская исходников и полные приватные снимки не зависят
от папки приложения. Сохранены 16 определений и 15 полных результатов скореров.
Это gold-контракты извлечения содержимого. Follow-up от 10 октября проверен:
**668/668 offline**, **668/668 cp1251**, **18/18 startup**, privacy исходников/staging,
точный manifest/ZIP и Setup из распакованного архива. Эти gates не удостоверяют
отображение в живом терминале или поведение модели.

| Следующий этап | Срок | Назначение |
| --- | --- | --- |
| Приёмка PK1 | Открыта | Первое/повторное меню, немедленная смена темы, удаление папки после выхода, live local/SSH chat/benchmark/resume |
| P1 — Anywhere — Linux | TBD | Терминальный Linux-клиент на общих контрактах и тех же наборах |
| U2 — Quick Compare | После P1 | Короткий candidate pack и подтверждение результатов по языкам |
| Reliable Runs — T5.3/T5.2 | После U2 | Проверка сбоев на реальных узлах и аппаратная сопоставимость отдельными поставками |
| RPT1 — Отчёты наборов | Backlog; порядок TBD | Engine-owned или декларативные schema-validated профили, без исполняемых шаблонов из наборов |
| LANG1 — Языковая методика | Исследование; порядок TBD | Более различающие парные задачи, ручная проверка и независимые scorer/content changes |

PK1 не переписывает prompts, scorers или inference pipeline и не реализует Linux.
Позднейшее языковое исправление отдельно версионировано: набор 1.0.1 / scorer v2
штрафует чужую письменность, сохраняя prompts/эталоны и исторический v1.
RU/EN-отчёт реализован; общего механизма профилей для других наборов ещё нет.
См. [границы follow-up](../FOLLOWUP_2026_10_10.md).
Авторские критерии используют существующую детерминированную оценку; открытые
задачи требуют человека. Прежние проверки кода требуют явного подтверждения;
для недоверенного кода нужна одноразовая VM.

Разделение настроек модели/теста, изолированные исполняемые проверки и
творческая/LLM-judge оценка остаются будущей работой. См.
[спецификацию](../PACK_LIBRARY_SPEC.md), [инструкции автора](PACK_AUTHOR_LLM.md)
и [мастерскую](AUTHOR_WORKSHOP.md).

Для Field Lab и Open Range номера релизов не назначены. GUI, публичный
лидерборд и marketplace не входят в ближайшие этапы. Содержимое и hashes
стабильного CHAT Core сохраняются; исправления scorer, новые задачи и runtime
изменяются с независимым версионированием и review.

Подробности: [roadmap и критерии приёмки](../BULL_TRANSITION_ROADMAP.md),
раздел `planned_roadmap` в [AI-контексте](../AI_CONTEXT.yaml).

## Правила изменений

Перед изменениями прочитайте [AGENTS.md](../../AGENTS.md),
[AI context](../AI_CONTEXT.yaml) и текущее руководство. Эти инструкции есть в публичном bundle.

- не выполнять big-bang rewrite;
- сначала фиксировать поведение regression tests, затем извлекать модуль;
- не менять prompts, scorers и runtime pipeline в одном изменении;
- разделять native model quality и client recovery;
- делать небольшие проверяемые commits;
- для релиза обновлять обе языковые ветки и `AI_CONTEXT.yaml`.

## Проверки

```powershell
.\Run-Tests.ps1
.\Test-Public-Release.ps1 -AuditReleaseCandidatesOnly
.\Build-Release.ps1
```

Suite проверяет benchmark/scorer contracts, resume, runtime fingerprints, порядок
запусков, typed shared contracts и UX/localization. `Run-Tests.ps1` компилирует
исходники и запускает полную offline-регрессию. Cp1251, синтаксис PowerShell,
privacy исходников/staging, manifest и ZIP — отдельные release gates
`Build-Release.ps1`; один запуск тестов не означает пересборку архива.
При каждом запуске приложения выполняются 18 обязательных проверок без кэша.
Setup и «Дополнительно → Диагностика → Полная регрессия» запускают полный suite.

Новое поведение требует focused regression test. Изменение методики benchmark
также требует golden fixtures и проверки false positive/false negative.

## Граница публичного релиза

Сборка выполняется из чистого checkout. Локальные результаты и secrets не входят
в package. Manifest сверяется со staging tree и ZIP, затем клиент проверяется из
распакованного релиза в offline-режиме и на одном локальном или synthetic пути.
До Setup в корне есть `Setup.exe`, но нет `BULL.exe`. Проверенный по manifest
`Setup/BULL.launcher.bin` превращается в клиент после полной регрессии и настройки/
пропуска связи. Проверяйте layout до и после установки. ZIP gate должен включать
все обязательные файлы, четыре базовых архива и исторический языковой fixture,
а не только прежнюю зафиксированную версию языкового ZIP.

Документы исходников и их хеши manifest могут обновляться отдельно от старого ZIP.
Синхронизация 11 октября требует нового архива/checksum через release pipeline;
не выдавайте прежний архив за актуальный. См. [готовность релиза](../RELEASE_READINESS.md).
Публикация остаётся отдельной; автоматические проверки не закрывают приёмку
терминала, выхода и live inference.

В GitHub release следует загружать bundle ZIP и его SHA-256. GitHub download
statistics считает загрузки release assets; source archives репозитория в этот
счётчик не входят.

## Участие в разработке

воспроизводимых дефектов. Опишите поддерживаемое решение, затронутую метрику,
evidence и compatibility impact. Prompts, scorers и runtime changes должны
оставаться независимо проверяемыми.
