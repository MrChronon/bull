# Библиотека наборов тестов

Для BULL v0.29.0.1 Pack Library.

## Первый запуск

Setup сначала предлагает язык и BULL Red / BULL Matrix, затем стандартные наборы,
свой локальный ZIP/явную HTTPS-ссылку либо пропуск. После полной регрессии из
668 проверок и настройки/пропуска связи создаётся `BULL.exe` и предлагается
запуск/выход. См. [последовательность установки](USER_GUIDE.md).

Позднее в **Главная → Настройки тестов** доступны:

1. **Установить базовый набор** — выбрать один или несколько необязательных ZIP из `BasePacks`.
2. **Импортировать свой ZIP** — указать локальный архив или HTTPS-ссылку на архив.
3. **Выбрать установленный набор и тесты** — использовать общую библиотеку.
4. **Пока пропустить** (`0`) — оставить доступными чат, подключения и отчёты.

Пропуск сохраняется между билдами и не устанавливает тесты. Вернуться можно
напрямую через **Главная → Настройки тестов**. Если для
сравнения нет выбранного набора, откроются те же варианты установки и выбора.
Установка ZIP не подменяет выбранную версию другой версией автоматически.

Введите один номер, несколько номеров через запятую (`1,3`) или `all`.
Массовая установка добавляет подтверждённые наборы в библиотеку, но не включает
их в прогон. Затем выберите одну установленную версию и все либо отдельные
задания. Стандартная установка в Setup выбирает `bull_chat_core` после успеха;
массовая установка через библиотеку сама активный выбор не меняет.
Идентичные установленные версии сохраняются; другое содержимое не
может перезаписать ту же версию. При частичной ошибке показаны успешные и
неудачные установки, уже установленные наборы остаются доступны.

## Где находятся наборы

Папка Windows: `%LOCALAPPDATA%\BULL\BenchmarkPacks`.

```text
BenchmarkPacks/
  Installed/public/<pack_id>@<version>/
  Installed/private/<pack_id>@<version>/
  Workspaces/<pack_id>-<unique_id>/  редактируемые исходники
  PackExports/                     собранные авторские ZIP
  Trash/<pack_id>@<version>-<unique_id>/
  .staging/                 временные данные установки
  library_state.json       первый запуск и явный выбор
```

Точный путь показан в меню; список установленных версий показывает их размер.
Он определяется по окружению текущего пользователя, а не записан с компьютера
разработчика. Просмотр без смены выбора: **Тестирование моделей → P** или
**Настройки тестов → 7**, сначала версия набора, затем его задания.
**Открыть папку библиотеки** открывает её в проводнике.
Библиотека находится вне приложения: распаковка нового билда не удаляет тесты.
ZIP можно получить у автора, например из его GitHub Releases. BULL не скачивает
и не публикует наборы автоматически.

**Удалить одну установленную версию** переносит именно эту версию в корзину BULL
(`Trash` внутри библиотеки, не системную корзину Windows).
Безвозвратного удаления нет. Trash продолжает занимать место: проверьте содержимое
и вручную удалите конкретную папку, если восстановление больше не нужно.
Для восстановления перенесите её в прежнюю ветку видимости и переименуйте
точно в `<pack_id>@<version>`, затем снова выберите набор.

Для чистого старта закройте BULL, сохраните нужные наборы и переименуйте именно
эту папку `BenchmarkPacks`. Новый запуск создаст пустую библиотеку только после
явного выбора при первом запуске. Не меняйте установленные версии вручную.
Не удаляйте целиком пользовательскую папку данных приложений.

## Установка и проверка

Укажите локальный ZIP или явно запросите скачивание архива по HTTPS-ссылке.
Сетевого каталога, фоновых загрузок и автоматических обновлений версий нет.
До подтверждения BULL проверяет пути, типы и
размеры файлов, manifest, хеши, совместимость движка и ссылки на скореры.
Предпросмотр показывает ID/версию, статус, видимость, источник, лицензию,
области и заявленные языки. Установка требует подтверждения. Перед размещением
архива его manifest и скомпилированное содержимое снова сравниваются с
подтверждённым предпросмотром.

Разрешены только данные: JSON, YAML, Markdown и TXT. Набор не может добавить
Python/PowerShell-код или импортировать свой скорер. Прежние проверки кода движка
требуют ввода `EXECUTE` при выборе этих заданий и не являются песочницей. Недоверенный код модели
проверяйте в одноразовой виртуальной машине.

Текущие лимиты: 1 000 заданий, 8 MiB на JSON/файл, 64 MiB архив, 128 MiB после
распаковки, 4 096 записей ZIP, коэффициент сжатия не выше 200. Для больших наборов
нужна будущая явная политика бюджетов; безлимитный размер пока не заявляется.

## Сравнение

Откройте **Тестирование моделей → Сравнить по набору тестов**. Выберите одну точную
установленную версию либо **Использовать текущий выбор**. Введите `all` или
неповторяющиеся номера тестов через запятую. `n` и `p` переключают страницы.
Набор может включать разные области, но два набора в одном прогоне не смешиваются.

В списке заданий показаны описания, ссылки на скореры, бюджеты автора и
ограничения. Затем выбираются модели, повторы/seeds и источник sampling.
Перед inference план показывает точные ID тестов, версию набора, покрытие и
итоговые runtime-параметры. Бюджеты тестов не меняют сохранённые настройки чата.
Чтобы проверить пригодность тестов для своей задачи, изучите промпты и критерии
в документации и файлах данных набора.

Для части тестов терминал и HTML явно показывают **ЧАСТЬ НАБОРА — не оценка
полного набора**. Баллы относятся только к этим заданиям. Если автоматического
скорера нет, сохраняются время и ответы для ручной оценки, без выдуманного
процента качества. Качество модели Native и восстановление клиента разделены.

Новые checkpoints наборов содержат полный приватный снимок заданий с хешами.
Смена выбора в меню, установка новой версии или удаление прежнего набора не
подменяют задания: resume читает сохранённые определения, а не библиотеку.
Изменение снимка или кода scorer/verifier блокирует исполнение. Восстановите
исходный checkpoint и движок; принудительное продолжение этого не обходит.
Старым checkpoints без полного снимка нужна точная установленная версия;
отсутствующие данные никогда не заменяются новейшей версией.

Приватный evidence сохраняет снимок. Share-safe JSON содержит только версию,
хеши manifest/compiled/snapshot и покрытие выбранные/все: без автора, промптов,
критериев и эталонных ответов. HTML поясняет покрытие и происхождение содержимого.
Перед отправкой проверьте ID набора/тестов и имена моделей: они могут раскрыть проект.

## Прежние функции

**Мои задачи и промпты** — отдельный прежний сценарий `UserTests`/промптов.
Свободные файлы не добавляются незаметно в набор. До мастерской автора их папка
остаётся внутри билда.

Именованные команды требуют набора со своими заданиями: языковые треки —
Language Comparison, CHAT — CHAT Core. `/bench pack list` показывает установленные
версии. Для проверки/просмотра одного набора нужен `PACK_ID@VERSION`, а не
неявный выбор последней версии.
Языковые треки выбирают совместимую установленную версию до обращения к моделям.
Текущий базовый Language Comparison — 1.0.1/scorer v2; 1.0.0 читается без
автообновления или пересчёта. См. [результаты RU/EN](RESULTS.md).

Повреждённая версия отображается как invalid и не выбирается. Другие исправные
версии доступны. Главная, чат и сохранённые отчёты работают без наборов.
Ошибки доступа к библиотеке исправляйте по показанному пути: BULL не создаёт
запасную библиотеку в рабочем каталоге. Если повреждён `library_state.json`,
закройте BULL и переименуйте именно этот файл, сохранив копию. Установленные наборы
не меняются; первый запуск и выбор начинаются заново.

Создание исходников: [инструкция для облачной LLM](PACK_AUTHOR_LLM.md).
В меню библиотеки доступна **Мастерская автора**: исходники, проверка успешных и
ошибочных ответов без inference, сборка ZIP для явного импорта.
См. [руководство мастерской](AUTHOR_WORKSHOP.md). Замороженные native-наборы
сохраняют собственные maintainer tools и не конвертируются автоматически в
keyword-задачи.
