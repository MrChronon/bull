# Подключения

## Выберите самый простой маршрут

| Где запущены модели | Меню BULL | Что требуется |
| --- | --- | --- |
| Этот компьютер | Подключение → Локальная Ollama | Запущенная локальная Ollama |
| Известный сервер | Подключение → Сохранённый сервер | Выбрать готовую запись |
| Сервер с рабочим OpenSSH alias | Подключение → Новый сервер по SSH-алиасу | Работает `ssh АЛИАС` |
| Новый сервер | Подключение → Новый сервер вручную | Адрес, user, ключ, проверенный fingerprint |

BULL не переключается с выбранного сервера на другой backend без решения
пользователя. При неудачном соединении настройки сохраняются.

## Локальная Ollama

Запустите Ollama и выберите **Локальная Ollama**. BULL использует loopback и не
открывает SSH. Роль AllInOne предназначена для клиента и моделей на одном ПК.

## SSH-алиас

Создайте отдельный ключ на клиенте:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\bull_access" -C "BULL client"
```

Добавьте на сервер в `authorized_keys` только `bull_access.pub`. Приватный файл
`bull_access` должен остаться на клиенте. Затем создайте запись OpenSSH:

```text
Host bull-home
    HostName SERVER_ADDRESS
    User SERVER_USER
    Port 22
    IdentityFile ~/.ssh/bull_access
    IdentitiesOnly yes
```

Проверьте `ssh bull-home` в PowerShell. В BULL выберите **Новый сервер по
SSH-алиасу** и введите `bull-home`. BULL получает `HostName`, `User`, `Port`,
`IdentityFile` и known-hosts через `ssh -G`, не используя shell. `ProxyCommand`,
`ProxyJump`, alias в виде опции и отсутствующий приватный ключ отклоняются.

Точное совпадение с OpenSSH `known_hosts` можно использовать как доверие. Если
совпадения нет, независимо проверьте SHA-256 fingerprint непосредственно на
сервере. Нельзя доверять fingerprint только потому, что его показало то же
непроверенное сетевое соединение.

## Ручная настройка SSH

Введите DNS/IP, SSH-порт, пользователя сервера, существующий приватный ключ и
независимо проверенный Ed25519 fingerprint. Мастер не устанавливает сервер, не
меняет роутер, не копирует ключ и не загружает модели.

Можно сохранить подключение для следующих версий BULL или только внутри текущего
билда. Постоянные записи хранятся в личном vault пользователя, настройки билда —
в `Runtime`. Эти данные не входят в релиз.

## Доступ через Интернет

Предпочтителен overlay VPN, например WireGuard или Tailscale. Для прямого SSH:

```text
PUBLIC_IP:EXTERNAL_TCP_PORT → SERVER_LAN_IP:22
```

Перенаправляйте только один TCP-порт. Не включайте DMZ/UPnP и не открывайте
Ollama `11434` или llama.cpp `8080`. Inference API должен слушать loopback и быть
доступен через SSH tunnel. До отъезда проверьте подключение из действительно
внешней сети, например через мобильный Интернет.

Используйте вход только по ключу, непривилегированную учётную запись, host-key
pinning и firewall. Для отзыва доступа удалите публичный ключ из
`authorized_keys`: удаление записи BULL само по себе доступ не отзывает.

## Диагностика

Пункт **Подключение → Помощь и диагностика** проверяет выбранный SSH-сервер без
запуска inference. Типовые причины:

- timeout: адрес, внешний порт, firewall, NAT или VPN;
- connection refused: OpenSSH или runtime не слушает порт;
- host-key mismatch: остановитесь и проверьте подлинность сервера;
- private key rejected: проверьте `authorized_keys`, права, user и ключ;
- tunnel работает, моделей нет: запустите Ollama и выполните `ollama list` на сервере.

В английском интерфейсе ошибки соединения не выводят русский текст старого
backend-кода. Исходная техническая причина сохраняется в `client_debug.log`.
