# Как читать результаты BULL

## Во время сравнения

Живая строка показывает текущий этап, прошедшее время и приблизительную скорость
генерации. Бюджет токенов — это ограничение, а не процент готовности задачи. CPU,
RAM, GPU и VRAM относятся к активному серверу моделей. Каждый показатель
содержит измерение либо `N/A` с причиной недоступности; отсутствие GPU/VRAM
не скрывается за одним сообщением CPU/RAM. Неизвестное не считается нулём.
Строка подстраивается под ширину терминала; в очень узком окне датчики сокращаются
до G/V/C/R.

После каждого сохранённого запуска выводятся Native-балл, Final-балл при отличии,
статус контракта, измеренная скорость и ресурсы. Следующая строка накапливает
данные только для текущих **модели + backend + теста**: число успешных запусков
и оценённых ответов, среднее качество Native и скорость генерации. Это
предварительный итог, а не рейтинг моделей с разным покрытием тестов.

## После сравнения

Общая сводка для обычных наборов начинается с трёх лучших **мест**, затем показывает номера моделей,
карту качества и скорости с числовыми осями, ресурсы и выполнение контракта.
Длинные имена переносятся под картой. Меню результатов предлагает HTML, файлы для
экспорта, свои приоритеты, ответы и отдельный пункт **Подробные метрики в терминале**.
Для просмотра результатов работающий сервер моделей не нужен.

Для RU/EN используется отдельное представление, описанное ниже. После открытия
HTML или ответов BULL ждёт возврата пользователя; следующая отрисовка очищает
меню, не меняя сохранённые результаты.

### Измеренные места и рекомендации — разные вещи

- **Качество Native:** наблюдаемый балл по убыванию, без результата recovery.
- **Скорость генерации:** токены в секунду по убыванию. При наличии warm-измерений
  используются только они; модели без warm-данных не подмешиваются в этот рейтинг.
  Если warm-данных нет вообще, явно указывается использование всех состояний загрузки.
- **Время задачи:** среднее записанное время всего pipeline по возрастанию,
  включая разрешённую помощь клиента. Больше токенов в секунду не обязательно
  означает меньшее время выполнения задачи.
- **Пик VRAM:** наблюдаемая память по возрастанию. Отсутствие датчика — не ноль.
  Это не минимальные аппаратные требования модели.
- **Баланс:** порядок по существующей формуле весов приоритетов, а не новый
  benchmark-балл. В HTML рядом отмечены модели, не прошедшие порог рекомендации.

Одинаковые значения делят место: например, 1, 1, 3. Все равные третьи места
сохраняются, поэтому в списке может оказаться больше трёх моделей. Близкие, но
разные средние задают только наблюдаемый порядок, а не доказанного победителя.

Рекомендации «Скорость», «Баланс», «Мало памяти» и собственные приоритеты требуют
консервативного качества Native не ниже
`max(60%, лучшее консервативное качество − 10 процентных пунктов)` и выполнения
контракта не ниже 80%, когда этот показатель известен. Консервативное качество —
нижняя граница 95% интервала, если она есть, иначе наблюдаемое среднее.
Без обязательных для профиля метрик кандидат не допускается.

Если прошла только одна модель, BULL прямо сообщает об этом. Она может получить
несколько рекомендаций, не будучи самой быстрой или экономной по фактическим
измерениям. Профиль «Качество» сохраняет отдельную взвешенную политику и не
применяет порог скоростных рекомендаций. Раздел **Места и причины** показывает
всех кандидатов и веса.

Разное записанное покрытие тестов/seeds, ошибки выполнения или перебор параметров
отключают рекомендации. Наблюдаемые измерения остаются видны. Одинаковое покрытие
само по себе не доказывает равенство оборудования, длины ответов и фоновой нагрузки.

## Общий HTML-отчёт

Отчёт использует выбранный в приложении язык: русский или английский. Он работает
без Интернета, JavaScript, CDN и внешних изображений.

1. **Топ-3:** измеренные места, баланс приоритетов, рекомендации и причины отказа.
2. **Качество и скорость:** точечная диаграмма Native-качества и токенов в секунду.
   Отдельная диаграмма времени использует секунды pipeline. Цвета и номера моделей
   одинаковы во всём отчёте; таблица даёт доступный текстовый вариант данных.
3. **Ресурсы:** средние CPU/GPU по измеренным запускам и пики RAM/VRAM. Это датчики
   всего узла с фоновыми процессами, а не выделенные ресурсы модели. Указано
   покрытие датчиков; неполные наблюдения ограничивают сравнение.
4. **Тесты:** цветовая таблица Native-качества, простые описания встроенных CHAT-тестов,
   число оценённых запусков и категории. Остальные тесты указаны по записанным
   идентификаторам без раскрытия приватного промпта или выдуманного описания.
5. **Параметры:** записанные контекст, лимит ответа, потоки, sampling, рассуждения,
   seeds и загрузка. В происхождении параметров видно, что передано в API, а что
   унаследовано. Несколько значений не заменяются одним.
6. **Все данные:** средние по тестам, неопределённость, диапазоны времени,
   критические замечания, ошибки выполнения/соединения и кривые контекста,
   если для них есть сопоставимые точки.

Шкалы качества используют 0–100%. Шкалы памяти относительны к максимальному
измеренному значению данного отчёта. Диапазон времени — наблюдаемый минимум–максимум,
а не доверительный интервал. SD показывает разброс; 95% интервал — неопределённость
оценки среднего.

**GEN** означает завершённую генерацию, **TASK** — соблюдённую обязательную структуру
и схему. Ни один показатель не гарантирует содержательную правильность. Final,
recovery и ошибки связи не смешиваются с качеством Native.

## Языковой отчёт RU/EN

**Тестирование моделей → Языковые треки** сначала предлагает подходящий
установленный набор и его точную версию, затем модели. Русский, английский
и парный режим используют задания этого набора, а не скрытый встроенный каталог.
Язык интерфейса не меняет язык теста.

Терминальная сводка и первая секция HTML разделяют RU и EN:

- **Критерии Native:** средний сохранённый балл автоматических проверок и число
  оценённых ответов `n`; это не экспертная оценка смысла.
- **Нужный язык:** доля ответов, прошедших языковую проверку, среди ответов,
  для которых результат этой проверки записан.
- **Без переключений:** доля успешных проверок чистоты основного текста.
  Конечный JSON исключён из определения языка: английские ключи не штрафуются.
- **Время Native:** среднее время первичного ответа до recovery, в секундах.
  **Warm tok/s:** только измеренные warm-запуски с числом наблюдений.
  Скорость зависит от токенизатора; она не равна качеству перевода.
- **Диапазон seed:** минимум–максимум средних баллов по seed и число seeds.
  Это описательный разброс, не доверительный интервал.
- **Покрытие:** учтённые запуски, ошибки и число точных пар. `N/A` означает
  отсутствие нужных измерений, а не провал или нулевой результат.

Парой считаются ровно один RU и один EN ответ одной модели с теми же backend,
digest, идентичностью набора/оценщика, seed/run и записанными условиями генерации
и runtime fingerprint. Неоднозначные попытки и ответы без пары не входят в
парные разности. Проверяйте количество пар, прежде чем сравнивать числа.

**Разница балла RU − EN** показана в процентных пунктах: положительное значение
означает больший балл RU в этих парах. **Разница времени RU − EN** — секунды:
положительное значение означает более долгий русский ответ. Также показаны
четыре исхода: все критерии выполнены в обоих языках / только RU / только EN /
ни в одном. Полный успех здесь требует полного балла, языка, чистоты текста
и выполнения Native task contract; он всё равно не доказывает предметную истину.

Общего языкового победителя нет. Дополнительные объединённые таблицы HTML
свёрнуты и явно не являются bilingual-рейтингом. Native и помощь клиента
остаются разными измерениями.

Текущий базовый набор **bull_language_comparison@1.0.1** использует scorer v2,
штрафующий чужую письменность в прозе. Prompts, эталоны и бюджеты сохранены от
1.0.0. Исторический v1 мог пропускать такие вставки; старый отчёт показывает
предупреждение, но scores не пересчитываются. Новая версия устанавливается
явно и не заменяет текущий выбор автоматически. Для исправленного измерения
нужен новый прогон по выбранной 1.0.1.

Шесть заданий проверяют ограниченный контракт. Даже 100% у всех моделей не
означает равную общую языковую компетентность: содержание и стиль требуют
ручного review. Общий механизм шаблонов для иных нестандартных наборов ещё
не реализован; он включён в [roadmap](../BULL_TRANSITION_ROADMAP.md).

## Передача и старые результаты

HTML не встраивает промпты, ответы, токены доступа, настройки соединения и приватные
пути. Имена моделей и тестов остаются видны — проверьте их перед публикацией.
Для передачи метрик используйте share-safe evidence JSON; raw JSON приватный.

Старые результаты не пересчитываются и не перезаписываются автоматически. Новый
сгенерированный отчёт использует новое оформление; ранее сохранённый HTML остаётся
прежним. Изменение отчётов не меняет промпты, scorers и настройки inference.
