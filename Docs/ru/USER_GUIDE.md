# BULL v0.29.0.1 — руководство пользователя

**Версия клиента:** v0.29.0.1

**Версия документации:** v0.29.0.1

**Актуализировано:** 11 октября 2026; документация стабильного релиза v0.29.0.1.
По решению владельца — latest stable; оставшиеся ручные проверки указаны отдельно.

Состояние автоматических проверок и незакрытая ручная приёмка:
[готовность релиза](../RELEASE_READINESS.md). Поведение исправлений от 10 октября сохранено.

[English guide](../en/USER_GUIDE.md) · [Русское руководство](USER_GUIDE.md)

Комплект GitHub подготовлен на двух языках: [состав и метаданные](../GITHUB_REPOSITORY.md),
[текст релиза](../../GITHUB_RELEASE_v0.29.0.1.md), [порядок публикации](RELEASING.md).
Перевод в stable не закрывает ручную приёмку и не меняет опубликованные ZIP/tag.
Документы в исходном архиве сохраняют прежнее описание; актуальный статус — здесь.

BULL — терминальное приложение для Windows для общения с языковыми моделями
и воспроизводимого сравнения их качества, скорости и ресурсов. Поддерживаются
Ollama и llama.cpp: локально или через защищённый SSH-туннель.

Наборы тестов отделены от движка. Один запуск использует одну точную версию
набора и все либо выбранные задания. Библиотека хранится в
`%LOCALAPPDATA%\BULL\BenchmarkPacks` и сохраняется при обновлении BULL.

## Требования и установка

Для приложения нужны Windows 11, Python 3.10+ и PowerShell. Модели и сервер
Ollama/llama.cpp устанавливаются отдельно; без них доступны настройки и отчёты.

1. Получите ZIP и соответствующий SHA-256, проверьте сумму и распакуйте в новую папку.
   Используйте ссылки конкретной версии в главном README или GitHub Releases:
   v0.29.0.1 отмечена как stable/latest; автоматический Source code не заменяет bundle ZIP.
2. Запустите `Setup.exe` (значок быка со стрелкой установки) и выберите English
   или Русский, затем **BULL Red** или **BULL Matrix**. Установка и приложение
   используют выбранные язык и тему. `Setup.cmd` — запасной вход.
3. Установите стандартные наборы, добавьте свой ZIP по HTTPS-ссылке или из файла,
   либо продолжите без тестов. Перед установкой показывается содержимое ZIP.
   Стандартная установка выбирает безопасный `bull_chat_core`; остальные наборы доступны в библиотеке.
4. Дождитесь полной внутренней регрессии: 668 проверок, без запросов к моделям.
   При ошибке можно повторить проверку или выйти; установка не считается завершённой.
5. Настройте существующее соединение: локальная Ollama, сохранённый сервер,
   SSH-алиас или ручные параметры. Можно пропустить и настроить позже в пункте 4.
6. После успешной проверки и настройки/пропуска соединения установщик создаёт `BULL.exe`,
   ярлыки в выбранном цвете и показывает готовность
   соединения и наборов. Выберите «Запустить BULL» или «Выйти из установщика».

Установщик не разворачивает сервер, не устанавливает модели, не меняет firewall
и не запрашивает права администратора. Если Python отсутствует, предлагается
его установка через winget с отдельным подтверждением.

Основной запуск: `BULL.exe` или созданный ярлык. `BULL-v0.29.0.1.cmd` использует
тот же вход. Отдельные launchers Benchmark Lab и Agent Lab
открывают соответствующие разделы.

При каждом запуске заново выполняются 18 обязательных регрессионных проверок
целостности, импортов, схем, ресурсов интерфейса и атомарной записи — без
использования сохранённого результата. Отдельное стартовое окно показывает текущую
проверку и реальный прогресс, затем закрывается до появления меню. Если Tk
недоступен, проверки всё равно идут в терминале. Ошибка блокирует запуск:
проверьте `client_debug.log` и выполните `Run-Tests.ps1`.

После проверки BULL проверяет выбранное соединение и пользовательскую библиотеку.
Два индикатора вверху главного меню показывают целостность и соединение.
Состояние наборов показывается в настройках тестов и тестировании моделей.
Зелёный означает подтверждённую готовность, жёлтый — необходимую настройку.
Возле пунктов меню эти состояния не повторяются. Нет соединения или наборов — настройки и сохранённые
отчёты остаются доступны. Подключение не заменяется автоматически другим backend.

Терминальный логотип рисуется цветными ячейками с обычными пробелами, без редких
символов шрифта. Все 24 строки выводятся и сбрасывают цвет отдельно; название
идёт после рисунка. Без поддержки цвета используется ASCII-силуэт.
Полная высота и одинаковая геометрия на реальном Windows Terminal ещё требуют
ручной приёмки, включая повторный запуск; перезапуск не считается исправлением.

## Главная

1. **Тестирование моделей** — запуск, продолжение и результаты.
2. **Чат с моделью** — новый или сохранённый диалог.
3. **Настройки тестов** — установка, выбор заданий, удаление и мастерская.
4. **Настройки соединения программы** — локальные модели, SSH и параметры движка.
5. **Настройки программы** — язык и цветовые темы.
6. **Дополнительно** — состояние сессии, диагностика, справка и эксперименты.
0. **Выйти**.

### Дерево основных маршрутов

```text
Главная
├─ 1 Тестирование моделей
│  ├─ 1 Сравнить по набору → набор/задания → модели → условия → план
│  ├─ 2 Задача из UserTests
│  ├─ 3 Мой промпт → новый / сохранённый
│  ├─ 4 Продолжить checkpoint
│  ├─ 5 Результаты → рекомендуемый HTML / сводка
│  └─ P Просмотр наборов → задания; L Языковые треки; ? справка
├─ 2 Чат → новый / сохранённый
├─ 3 Настройки тестов
│  ├─ 1 Базовые ZIP; 2 файл ZIP или HTTPS-ссылка
│  ├─ 3 Выбор набора/заданий; 4 перенос версии в корзину BULL
│  └─ 5 Папка библиотеки; 6 мастерская автора; 7 просмотр наборов → задания
├─ 4 Настройки соединения программы
│  ├─ 1 Локально; 2 сохранённый сервер; 3 SSH-алиас; 4 вручную
│  ├─ 5 Импорт JSON; 6 перенос; 7 проверка SSH
│  └─ 8 Ключ/алиас; 9 Интернет; 10 забыть запись; 11 параметры движка
├─ 5 Настройки программы
│  └─ 1 Язык; 2 BULL Red; 3 BULL Matrix
├─ 6 Дополнительно
│  ├─ 1 Состояние сессии; 2 диагностика программы и API
│  ├─ 3 Как пользоваться; 4 справочник команд
│  └─ 5 Agent Benchmark
└─ 0 Выход
```

`0` возвращает назад. На главной и в чате доступны точные `/команды`.
Для обычного сравнения знать их не требуется. Тема по умолчанию красная BULL;
альтернатива — BULL Matrix. Успех всегда зелёный, предупреждение жёлтое,
ошибка красная независимо от темы.

В разделе **Настройки программы** пункт `3` или ввод `BULL Matrix` включает
зелёного быка и зелёные акценты с голубыми действиями. Тема применяется сразу,
сохраняется после перезапуска и не меняется при смене языка. При следующем запуске
загрузочное окно тоже будет зелёным: прежняя композиция BULL, рамка и полоса
прогресса в палитре Matrix. Справа от быка движутся вертикальные столбцы цифр
и символов. Они остаются в пределах рисунка и не перекрывают версию, название
проверки или прогресс. В меню и при тестировании моделей анимации нет.
Выбор BULL Red возвращает красное оформление и
красный загрузочный экран. Настройки относятся
к этой папке приложения; `BULL_UI_THEME`, если задана, переопределяет их при запуске.
UTF-8 и режим цветов проверяются перед первым меню после стартовых проверок
и при выборе темы. Без поддержки цвета используется ASCII-силуэт быка.
При смене темы меняются и значки существующих ярлыков BULL на рабочем столе
и в меню «Пуск». Ярлыки другой установки не перезаписываются. Высококонтрастная
тема удалена; старый выбор переводится в BULL Red, старые Matrix-варианты — в
BULL Matrix. Терминальный рисунок имеет 48×24 ячейки вместо 30×15.
Setup и BULL используют одинаковый профиль Windows Terminal, если он доступен;
для обычной консоли применяется единый шрифт Consolas. Глобальные настройки
Windows Terminal и шрифта не меняются.

## Подключение к моделям

Откройте **Настройки соединения программы** и выберите источник:

- **Локальная Ollama** — модели установлены на этом компьютере;
- **Сохранённый сервер** — подключение уже настроено в BULL;
- **Новый сервер по SSH-алиасу** — команда `ssh АЛИАС` уже работает;
- **Новый сервер вручную** — ввод адреса, SSH-порта, пользователя, приватного
  ключа и независимо проверенного fingerprint сервера.

Импорт, перенос, проверка SSH и инструкция доступа через Интернет находятся в
разделе инструментов подключения. Запущенная Ollama не нужна для открытия меню,
настроек, справки и сохранённых отчётов. Чат и новый прогон проверяют выбранное
подключение непосредственно перед запуском.

Настройка и диагностика подробно описаны в разделе [Подключения](CONNECTIONS.md).

## Сравнение моделей

### Сравнить набор тестов

Откройте **Тестирование моделей → Сравнить по набору тестов**, выберите набор и все либо
отдельные задания, затем модели, проверьте план и запустите тест. Стандартные настройки используют одинаковые определения
тестов и сопоставимые условия для каждой модели. Меняйте runs, seeds, reasoning
или параметры генерации только когда этого требует эксперимент.

### Мои задачи и промпты

Откройте **Тестирование моделей → Задача из UserTests** или **Мой промпт**. Можно выбрать файл из
`UserTests` или вставить разовый prompt. Задача `.txt` измеряет runtime и сохраняет
ответы для ручной проверки; BULL не выдумывает quality score. Строгий `.yaml`
может использовать только поддерживаемые детерминированные критерии.

### Восстановление прерванного прогона

Завершённые runs атомарно записываются в checkpoint. Пункт **Продолжить
прерванный тест** выполняет только отсутствующую или прерванную работу. Если
сервер выключен, настройки и готовые runs сохраняются: восстановите связь и снова
запустите resume. Несовпадение окружения блокирует обычный resume; принудительный
режим предназначен только для осознанного экспертного использования.

При временной блокировке checkpoint Windows BULL повторяет замену файла.
Если запись остаётся заблокированной, прогон останавливается: прежний файл
не перезаписывается, а полностью записанная копия сохраняется рядом с ним.
Путь копии показан в сообщении. Закройте другие экземпляры BULL и программы,
удерживающие файл, затем выберите **Продолжить прерванный тест**. Восстановление
из копии требует подтверждения и создаёт новый checkpoint; оба исходных файла
сохраняются. Через команду можно явно указать копию: `/bench resume "ПУТЬ"`.

### Ресурсы во время тестирования

В текущей строке и после сохранения задания показаны CPU, RAM, GPU и VRAM
узла, на котором работает модель. CPU/GPU — загрузка, RAM/VRAM — занятая
память; в итоговой сводке используются средняя загрузка и наблюдаемые пики.
Это ресурсы всего узла, включая фоновые процессы, а не расход одной модели.
CPU/RAM Windows собираются без WMI и прав администратора. При SSH-подключении
измеряется сервер, а не клиентский компьютер. Каждый из GPU, VRAM, CPU и RAM
показывает измерение либо `N/A` с причиной, а не ноль. Отсутствие необязательного
датчика температуры/мощности не скрывает GPU/VRAM. Старые отчёты не дополняются
выдуманными измерениями.

### Проверки при запуске

Отдельное окно показывает рисунок BULL в выбранной красной или Matrix-теме, текущую версию,
название выполняемой проверки и процент завершённых проверок. Запуск
проверяет 18 обязательных контрактов: целостность движка и интерфейса,
импорт модулей, схемы и запись JSON. Полная регрессия предназначена для
установки, разработки и сборки релиза: `Run-Tests.ps1`; она также доступна
через **Дополнительно → Диагностика программы → Полная регрессия**.
Сейчас в ней 668 проверок, без inference. При запуске проверки
выполняются заново, без кэшированного результата. Пользовательские настройки
и установленные наборы не обязаны совпадать с заводскими; выбранный набор
проверяется отдельно перед прогоном.

### Просмотр результата

Для обычных наборов после прогона BULL предлагает:

- краткую сводку прямо в терминале;
- измеренный топ-3 по качеству Native, скорости генерации, VRAM и взвешенному
  балансу, а также отдельные рекомендации с порогом допуска;
- собственные веса важности;
- диаграммы качества/скорости и времени задачи с числовыми осями и стабильными
  номерами моделей;
- автономный HTML-отчёт — рекомендуемый следующий шаг: карточки
  «качество / контракт / скорость», две диаграммы рассеяния (качество ↔ скорость
  и качество ↔ время задачи), диапазон стабильности по seed, ресурсы и heatmap;
- share-safe summary и явно помеченные приватные raw-данные.

Рекомендации относятся только к текущему прогону. Они используют измеренные
метрики и quality/task gates, но не являются универсальным рейтингом или новым score.
Языковые прогоны используют специализированную RU/EN-сводку, а не общий
«языковой топ-3». После возврата из HTML/ответов меню очищается и рисуется заново.

### Русские, английские и bilingual-треки

`language_ru` и `language_en` измеряют автоматические критерии и скорость отдельно для русских
и английских prompts. Парные задачи имеют одинаковые смысл, JSON-контракт,
контекст и лимит ответа; меняется только язык задания.

```text
/bench language_ru MODELS
/bench language_en MODELS
/bench bilingual MODELS
```

`/bench bilingual` запускает обе версии каждой задачи в одном сбалансированном
плане. Сравнивайте Native score, выполнение контракта, warm tok/s и wall time
внутри каждого языкового трека. Не складывайте русские и английские баллы в одно
число качества. В интерфейсе: **Тестирование моделей → Языковые треки**.
Сначала выберите совместимую установленную версию набора; задания проверяются
до обращения к моделям. Базовая 1.0.1 использует scorer v2: вставки чужой
письменности в основной текст штрафуются. Старый scorer v1 сохранён для 1.0.0,
установленные версии и результаты не обновляются и не пересчитываются автоматически.
Scorer также проверяет язык основного текста ответа; JSON
в конце ответа не используется для определения языка.

RU/EN-отчёт разделяет Native-критерии, нужный язык, чистоту текста, время,
warm tok/s, покрытие и диапазон средних по seed. Разности RU − EN считаются
только для точных пар по модели/digest, backend, набору/оценщику, seed/run
и записанным параметрам. Нет пары — нет парной разности; общего победителя нет.
Шесть задач не являются полной смысловой оценкой: 100% не доказывает общую
языковую компетентность. Подробное чтение метрик: [Результаты](RESULTS.md).

Во время прогона live-строка может показывать приблизительную скорость, GPU/VRAM
и агрегированные CPU/RAM активного inference-host. После каждого сохранённого run
BULL выводит короткий checkpoint: native/final score при наличии scorer, TASK,
скорость и доступные измерения ресурсов. Отсутствующий датчик не заменяется нулём.

Как читать места, рекомендации, ресурсы и диаграммы — в [Результатах](RESULTS.md).
Определения метрик и формат собственных тестов приведены в [Бенчмарках](BENCHMARKS.md).

## Чат

Выберите модель и используйте FAST для обычных ответов, THINK для поддерживаемого
reasoning или ULTIMATE для ограниченного продолжения тяжёлой задачи. Диалоги можно
сохранять, открывать, ветвить и экспортировать, а также прикреплять файлы.
Выполнение tools и сгенерированного кода не является OS-песочницей. Недоверенный
код запускайте только в отдельной VM без секретов и доступа к сети.

Dashboard отличает живой backend от сохранённых данных сессии. В offline-режиме
он не выдумывает состояние модели, GPU, VRAM или соединения.
Модель, заведомо не поддерживающая THINK, работает в FAST. Явный HTTP 400
«does not support thinking» допускает один повтор без THINK только в чате
с выключенными tools; другие ошибки и benchmark-политика не подменяются.
До начала диалога состояние показывает конфигурацию, не активную сессию;
пустой чат не сохраняется автоматически.

## Дополнительно

Пункт 6 главной открывает плоский список инструментов: состояние текущей сессии,
диагностику программы и доступности API, руководство и справочник команд,
Agent Benchmark. Диагностика предлагает базовые проверки либо полную регрессию,
как в Setup. Проверка API не генерирует ответы модели. До первого чата состояние
показывает только конфигурацию, без активной сессии и контекста.
Экспериментальные инструменты помечены отдельно; обычное сравнение их не требует.
`0` возвращает на главную. Дополнительного меню «Эксперименты» нет.

## Библиотека наборов тестов

В настройках тестов выберите базовый ZIP из `BasePacks`, свой ZIP
из файла/по явно указанной HTTPS-ссылке,
установленный набор или пропуск. Пропуск запоминается. Вернуться можно через
**Главная → Настройки тестов**. Базовые ZIP можно установить списком номеров или
через `all`; для прогона по-прежнему выбирается одна версия. Общая папка Windows:
`%LOCALAPPDATA%\BULL\BenchmarkPacks`, вне папки приложения.
Меню показывает путь, версии, заявленные навыки и языки. Удаление переносит
точную версию в восстанавливаемую корзину BULL (папка `Trash`), не затрагивая ключи, подключения и результаты.
ZIP содержит только данные; установка ограничена по размеру и требует подтверждения.

Для просмотра без смены выбора: **Тестирование моделей → P** или
**Настройки тестов → 7**. Сначала открываются версии наборов, затем задания
выбранной версии. Статус библиотеки показывается в этих разделах, не на главной.

[Мастерская автора](AUTHOR_WORKSHOP.md) создаёт UTF-8 YAML/TXT исходники,
проверяет успешные и ошибочные примеры ответов и собирает ZIP новой версии:
без автоматической установки или публикации. Передайте облачной LLM полную
[инструкцию автора](PACK_AUTHOR_LLM.md) и руководство мастерской, затем проверьте
предметные эталоны самостоятельно. Для TXT доступна ручная оценка качества,
а не выдуманный автоматический балл.

Новые checkpoints и private evidence сохраняют полный снимок заданий.
Удаление или обновление набора не заменяет задания при resume. Повреждённый
снимок или изменённые проверки движка блокируют запуск. Старым checkpoints
без снимка нужна точная установленная версия. Share-safe JSON передаёт
только разрешённые метаданные, хеши и покрытие, а не полный снимок.

[Пошаговое руководство](PACK_LIBRARY_GUIDE.md) описывает выбор, частичные
прогоны, версии, удаление и восстановление. Требования и форматы:
[спецификация](../PACK_LIBRARY_SPEC.md) и [мастерская](AUTHOR_WORKSHOP.md).

## Файлы результата

Прогон может создать raw JSON/CSV, атомарный checkpoint, summary JSON/CSV,
tested profiles, private evidence, share-safe evidence и автономный HTML.
Raw-ответы, prompts, локальные пути и подключения могут быть приватными.
Проверяйте файлы перед публикацией.

## Диагностика

- **Локальная Ollama не запущена:** запустите её или выберите сохранённый SSH-сервер.
- **WinError 10054:** соединение разорвано; восстановите сеть/сервер и выполните resume.
- **WinError 10061:** endpoint отклоняет соединение; проверьте SSH, runtime и tunnel.
- **Regression failed:** запустите `Run-Tests.ps1`; не проводите тест до успешной проверки.
- **Кракозябры:** используйте штатный launcher, который настраивает UTF-8.
- **Разная ширина или обрезанная высота быка:** Setup, его кнопка
  запуска и ярлык теперь используют единый BULL.exe и профиль терминала.
  Для окончательной приёмки сравните первое меню после Setup.exe и повторный
  запуск ярлыком: полный рисунок, название под ним и одинаковый текст.
  Вывод исправлен на отдельные строки, но реальный терминал ещё требует приёмки.
- **Папка приложения не удаляется после выхода:** BULL завершает только собственные
  sampler/SSH-процессы и закрывает их потоки; отдельный сервер моделей не останавливает.
  Все блокировки Windows не считаются доказанно устранёнными. Закройте окно
  BULL и открытые в этой папке терминалы; при повторении приложите локальный лог
  и список удерживающих процессов, без завершения посторонних серверов.
- **Старое сообщение backend не соответствует языку UI:** техническая причина
  сохраняется в `client_debug.log`, а интерфейс показывает локализованный путь восстановления.

## Приватность

Публичный bundle не содержит `Chats`, `Runtime`, `Benchmarks`, `Exports`,
`Workspace`, приватные ключи, подключения и локальные логи. Не открывайте Ollama
`11434` или llama.cpp `8080` напрямую в Интернет. Перед удалённой работой и
публикацией результатов прочитайте раздел [Безопасность](SECURITY.md).

Если отсутствуют библиотеки аналитических проверок, установщик предлагает
с подтверждением загрузить их из PyPI в отдельное окружение `Runtime/Python`.
Системные Python-пакеты не меняются. Все launchers используют Python,
которым успешно пройдена проверка установки.
