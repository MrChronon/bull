# Экспериментальная GPU Lab v1 — Windows + Ollama

Вход: **Тесты и результаты → 7. Экспериментальная GPU Lab**, либо `/gpu` с главной.
Это отдельный инструмент измерения производительности. Он не меняет готовые
benchmark prompts, scorers, чат, Agent Benchmark и рабочие настройки backend.
Начиная с v0.22 приложение называется BULL. Ребрендинг
не создаёт новый формат подключения, не меняет путь к ключам и не меняет GPU workload.

## Перед первым запуском

1. На компьютере с картами должны работать Windows, `nvidia-smi` и Ollama.
   Обе карты должны быть видны одному драйверу. Убедитесь в нормальном охлаждении
   и питании: P100 часто требует отдельного направленного воздушного потока.
2. Модели скачайте заранее. GPU Lab не скачивает модели, не исполняет сгенерированный
   код и запрещает cloud-модели. Автоматическая установка драйверов не выполняется.
3. В **Подключениях** выберите этот компьютер либо Windows-сервер по SSH с закреплённым
   host key. Путь и каталог моделей относятся к Windows-пользователю на сервере.
   Запущенная основная Ollama не обязательна; подключение по SSH должно работать.
4. Если Ollama или модели установлены нестандартно, откройте **GPU Lab → Пути на сервере**.
   Задайте абсолютный путь к `ollama.exe` и каталогу моделей, не командную строку.
   Пустое значение — автоопределение. Настройки приватны и относятся к текущему билду;
   при переключении на другой сервер проверьте их. Основной `backend_settings.json` не меняется.
5. Самостоятельно остановите другие вычисления и выгрузите модели, занимающие выбранные
   GPU. Лаборатория не завершает чужие процессы. Обнаруженная занятость ставит эксперимент
   на паузу. Скрытую драйвером нагрузку исключить автоматически невозможно.

По актуальной документации Ollama, P100 имеет CUDA compute capability 6.0; для
GPU 5.0–6.2 указана версия драйвера 570+. Реальная совместимость зависит от установленной
сборки Ollama и драйвера; наличие имени карты в списке не гарантирует CUDA inference.
См. [Ollama GPU support](https://docs.ollama.com/gpu) и
[NVIDIA legacy compute capability](https://developer.nvidia.com/cuda/gpus/legacy).
Драйвер не обновляется автоматически; проверьте поддержку обеих карт перед установкой.

## Сценарий RTX 3060 / P100 / обе

1. Новый эксперимент → выберите RTX 3060 и P100 из обнаруженного списка.
2. Выберите **сравнить каждую отдельно и все вместе**. Получатся три конфигурации.
   В точном режиме можно оставить только одну или две из них. Устройства адресуются
   стабильными GPU UUID, не изменяемыми после reboot номерами CUDA.
3. Подтвердите чтение каталога — временная Ollama запустится без загрузки модели.
   Выберите одну или несколько уже установленных моделей.
4. Выберите генерацию текста, генерацию кода **без исполнения**, длинный вход или свой промпт.
   Это versioned performance workloads, не существующие quality benchmarks.
5. Начните с быстрого smoke: одна небольшая модель, один сценарий, один повтор.
   Для сравнения используйте стандартные три повтора. Экспертные настройки:
   контекст 4096–32768, выход 32–2048 токенов, 1–10 повторов, таймаут 30–1800 секунд.
   Максимум — 120 пар запросов в одном эксперименте.
6. Проверьте план и явно подтвердите **запуск нагрузки**. Enter не запускает тест.

Каждая пара: новый изолированный процесс → первый запрос → тот же запрос повторно →
остановка только своего процесса и его дочерних runners. Порядок GPU, моделей и
сценариев циклически меняется между повторами. Это снижает систематический эффект
очерёдности, но не устраняет температуру, дисковый/файловый кеш и фоновую нагрузку.

## Что реально означает выбор GPU

Лаборатория передаёт **только своему процессу** `CUDA_VISIBLE_DEVICES` с выбранными UUID.
Для комбинации выставляется `OLLAMA_SCHED_SPREAD=1`. Vulkan и альтернативные GPU
backends отключены; Flash Attention отключён и KV cache f16 фиксирован для сопоставимости
Pascal/Ampere. Не задаются глобальные environment variables, режим питания или разгон.
Обычный сервер/автозапуск Ollama не перезапускается. Две карты не обещают удвоения скорости.

Разделены:

- запрос запуска: GPU UUID, environment, Ollama version, model digest, request hash;
- наблюдаемое размещение: GPU UUID процессов, принадлежность Windows Job Object;
- фактические показатели `/api/ps`: общий объём модели/VRAM и контекст, когда доступны;
- датчики всей карты: память, загрузка, температура, мощность — это не потребление только модели.

Статусы размещения: `observed_selected`, `partial`, `unverified`, `unexpected_device`.
Процесс должен наблюдаться на каждой выбранной карте. Чужая загрузка не считается
подтверждением. CPU-only, неизвестный offload, неполное подтверждение и неизвестная
фоновая нагрузка исключаются из подтверждённых сравнений, но сохраняются для диагностики.
Residency процесса не доказывает равномерность вычислений между картами. WDDM или
драйвер могут скрыть процессы/память: неизвестное остаётся неизвестным, а не нулём.

## Результаты

Сразу в терминале: конфигурации, число подтверждённых измерений, decode tok/s,
SD, min/max, TTFT клиента, полное время, prefill tok/s и раздельные датчики карт.
В **Результаты и продолжение** доступны тот же обзор, путь к HTML и продолжение.
HTML автономный, без скриптов/CDN, со сравнительными полосами внутри одинаковых
модели/сценария/фазы/load-class. CSV — плоская сводка. Универсального рейтинга нет.

`Benchmarks/GPU/<run-id>/`:

- `result.private.json`: schema `bull-gpu-experiment`, version 1; конфигурация,
  UUID, точный пользовательский промпт, план, fingerprints, попытки, измерения, события.
  Это **приватный checkpoint**, не файл для GitHub. Сгенерированные ответы не сохраняются.
- `summary.csv`, `report.html`: показатели без prompts, ответов, адресов, SSH-логинов,
  путей моделей и UUID. Имена моделей/карт видны: проверьте их перед публикацией.
- `result.private.json.lock`: OS-блокировка записи; снимается ОС после падения процесса.

Первый запрос обозначает fresh process, **не холодный дисковый кеш**. Повтор того же
промпта допускает KV cache hit. Warm классифицируется отдельно по фактическому
`load_duration ≤ 100 ms`, не по номеру запроса/seed. TTFT включает SSH/сеть и может
включать thinking; decode/prefill durations поступают от Ollama. Разные модели могут
генерировать разное число токенов. Limit/stop reason и counts остаются в JSON; это не
оценка выполнения задания. SD при одном измерении отсутствует. CI/rank/Pareto пока
не рассчитываются — нельзя выдавать эти малые выборки за достоверное ранжирование.
До 61 точки датчиков сохраняется на запрос; пики относятся к сохранённой выборке.

## Сбои и защита процесса

Ctrl+C или ошибка запроса — пауза с атомарной записью. Откройте результат и выберите
продолжение. Полностью завершённые пары не повторяются; незавершённая пара архивируется
как попытка и начинается с нового процесса. Смена inventory/driver, версии Ollama,
digest модели, workloads или конфигурации требует нового эксперимента.

Супервизор запускается через локальные pipes или существующий pinned SSH. Ollama слушает
случайный **loopback-only** порт; remote API доступен через отдельный SSH forward.
Проверяется принадлежность слушающего порта запущенному процессу. Windows Job Object
с kill-on-close удерживает только его и дочерние процессы. При EOF управляющего канала,
падении супервизора либо 60 секундах без команд job закрывается. Есть один server-side
mutex на GPU Lab; параллельные эксперименты блокируются. Машинный reboot завершает
процессы; после reboot запускается новый супервизор, сохранённые пары остаются на клиенте.

Температура опрашивается примерно раз в 5 секунд, без гарантии реального времени.
При наблюдении ≥85°C собственный job останавливается. Это дополнительная защита,
**не замена аппаратной термозащите или охлаждению**. Ошибка канала или запроса датчиков
прекращает эксперимент; отдельные N/A показатели сохраняются как неизвестные, и
температурная защита при N/A температуры недоступна. Чужие процессы, драйвер и службы не трогаются.

## Что проверено и чего пока нет

Offline tests проверяют протокол, JSON, PID/порт, Windows Job cleanup включая дочерний
процесс и аварийное завершение супервизора, pause/resume, метрики и приватность отчёта
на синтетических executable/API без моделей и без GPU-нагрузки. Реальный прогон
RTX 3060 + P100 и WAN SSH ещё нужен на пользовательском сервере. Linux, llama.cpp,
Agent/quality matrices по GPU и проверка точной доли вычислений каждой карты — не
часть GPU Lab v1. Обычные тесты/Agent работают как прежде вне экспериментального раздела.
