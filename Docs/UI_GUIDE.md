# Интерфейс BULL v0.28.0.2

[Руководство на русском](ru/USER_GUIDE.md) · [English user guide](en/USER_GUIDE.md)

v0.27 использует терминальный интерфейс. Его задача — провести нового
пользователя от подключения моделей к понятному сравнению без знания внутренних
команд BULL. Графический GUI не входит в этот этап.

## Первый запуск

Перед главным меню BULL показывает версионный стартовый экран с красным знаком
быка, номером текущей версии и ходом обязательной проверки клиента. Прогресс
обозначает только реально наблюдаемые этапы: проверка состава файла, запуск
офлайн-регрессии и успешное завершение. BULL не рисует выдуманный счётчик
отдельных тестов. Изображение является локальным, заранее подготовленным ANSI
ресурсом: приложению не нужен Chafa, просмотрщик изображений или сеть во время
запуска. Для каждого релиза создаётся отдельный asset с номером версии.

После успешной проверки BULL очищает стартовый экран и продолжает обычный
offline-first запуск. Выбор **English / Русский** появляется только при первом
запуске. Язык сохраняется и позднее меняется в **Дополнительно → Язык и внешний
вид**. Benchmark prompts, ответы моделей и измерения никогда не переводятся
автоматически.

На каждом следующем экране выводятся полная пиксельная голова быка и расшифровка
названия. Они служат устойчивым визуальным ориентиром, но не заменяют заголовок
и breadcrumb. Переход между страницами очищает предыдущий экран, поэтому меню и
мастера не накладываются друг на друга.

## Главное меню

На первом уровне ровно четыре пользовательских действия:

1. **Сравнить модели** — основной сценарий BULL.
2. **Чат с моделью** — новый или сохранённый диалог.
3. **Подключение** — модели на этом компьютере или на SSH-сервере.
4. **Дополнительно** — результаты, внешний вид, диагностика, справка и
   экспериментальные функции.

`0` всегда означает возврат или выход. Опытный пользователь может ввести `/`
команду прямо на главной, но команды не конкурируют с основным сценарием.
Обычный текст модели вводится только в чате.

## Основной сценарий сравнения

**Сравнить модели → Стандартное сравнение**:

1. выбрать установленные модели;
2. оставить стандартные одинаковые условия или явно открыть настройки;
3. проверить план;
4. запустить;
5. прочитать сводку в терминале;
6. при необходимости открыть HTML или взять share-safe JSON.

**Сравнить модели → Мои задачи и промпты** предлагает два пути:

- задача из `UserTests` — повторяемый `.txt` или `.yaml` файл;
- один вставленный prompt — быстрый эксперимент с историей версий.

Стандартный режим использует три seed. Быстрый режим с одним seed подходит для
проверки запуска, но не даёт вывода об устойчивости ранжирования.

## Результат без выхода из BULL

После завершения доступны:

1. краткая сводка в терминале;
2. выбор по собственным приоритетам;
3. полный автономный HTML;
4. пути к файлам для экспорта;
5. raw-ответы моделей;
6. повтор того же теста;
7. другой тест.

Терминал и HTML показывают одни и те же четыре профиля выбора:

- **Качество** — приоритет наблюдаемой средней Native quality. При нескольких
  runs нижняя граница 95% CI может отдельно использоваться как консервативная
  величина выбора и всегда подписывается отдельно от среднего балла;
- **Скорость** — приоритет warm tok/s после quality/task gate;
- **Баланс** — совместный учёт качества, скорости, выполнения контракта и VRAM;
- **Мало памяти** — больший вес экономии VRAM после того же gate.

Пункт **Мои приоритеты** принимает веса 0–100 для качества, скорости, выполнения
контракта и VRAM. Сумма нормируется автоматически. Эти значения не меняют score,
не пересчитывают ответы и не создают универсальный рейтинг.

Карта «Native quality ↔ скорость» строится по наблюдаемой средней Native quality
и относительна только моделям текущего прогона.
Правый верхний сектор означает лучшее сочетание двух наблюдаемых показателей;
левый верхний — акцент на качестве; правый нижний — скорость при необходимости
ручной проверки; левый нижний — слабый результат внутри данного набора. При
одинаковой utility нескольких моделей BULL показывает равноценных кандидатов,
а не выбирает модель по её имени. При недостатке сопоставимых метрик BULL не
рисует победителя.

HTML и share-safe evidence предназначены для передачи. Raw JSON может содержать
prompts и ответы, поэтому интерфейс явно помечает его как приватный.

## Пользовательские задачи

В `UserTests` лежат два шаблона. `.txt` отправляется моделям как prompt и не
получает выдуманного quality score. `.yaml` использует только объявленные
детерминированные проверки. Полный контракт, допустимые критерии, правила весов,
critical cap и примеры описаны в `Docs/USER_TESTS.md`.

Ошибочный пользовательский файл не блокирует остальные: BULL показывает имя и
причину отказа. Файлы ограничены по размеру и не могут исполнять Python, shell,
YAML tags, aliases или регулярные выражения.

## Подключение

Обычный экран сгруппирован по месту запуска моделей и содержит:

1. **На этом компьютере** — локальная Ollama на `localhost`;
2. **Удалённый сервер** — выбрать сохранённый сервер;
3. **Удалённый сервер** — добавить его по существующему SSH-алиасу;
4. **Удалённый сервер** — добавить вручную;
5. **Инструменты** — импортировать Connection JSON или перенести старую запись;
6. **Помощь и диагностика** — явная проверка SSH, инструкции и удаление записи.

Если `ssh bull-home` уже работает по ключу, достаточно выбрать пункт 3 и ввести
`bull-home`. BULL читает `HostName`, `User`, `Port` и `IdentityFile` через
`ssh -G`, проверяет host key и не копирует приватный ключ. Проверки соединения не
запускаются сами по себе: пользователь явно выбирает действие. Подробнее:
`Docs/SSH_QUICKSTART.md`.

## Дополнительные функции

Раздел **Дополнительно** содержит сохранённые результаты, единый экран языка и
внешнего вида, состояние сохранённой сессии, справку и точные команды. Экран
состояния при недоступном backend не выдаёт сохранённые данные за живую
диагностику. В **Экспериментальных функциях** находятся
Agent Benchmark, GPU Lab и расширенные настройки движка/сервера. Функционал
сохранён, но не мешает основному сравнению.

## Цвет и доступность

| Отображение | Значение |
| --- | --- |
| Голубой номер и название | Доступное действие |
| Светлый текст | Информация |
| Зелёный + `OK` | Подтверждённый успех |
| Жёлтый + `ВНИМАНИЕ` | Нужна проверка |
| Красный + `ОШИБКА` | Действие не выполнено |

Цвет не является единственным сигналом. Все важные состояния имеют текстовую
подпись. Тема по умолчанию — бирюзовая **BULL**. В **Дополнительно → Язык и
внешний вид** доступны темы **BULL**, **Matrix**, красная **BULL Red** и
высококонтрастная; там же меняется язык.

## Приёмочные сценарии

- При выключенной Ollama открываются главная, подключение, помощь и результаты.
- Новый пользователь запускает стандартное сравнение без `/bench`-команд.
- Agent/GPU/server setup отсутствуют на первых двух уровнях основного сценария.
- `.txt` не получает автоматического quality score.
- Неверный `.yaml` изолируется с понятной ошибкой до inference.
- После multi-model прогона терминал показывает профили и двумерную карту.
- Пользовательские веса не меняют сохранённые benchmark scores.
- HTML не содержит raw prompts/answers; raw JSON помечен приватным.
- Английский и русский маршруты не смешивают языки интерфейса.
- Повторный запуск использует сохранённый язык без стартового вопроса.
- Недоступная Ollama не создаёт ложный `OK` и не запускает live telemetry.
- Каждая страница очищает предыдущую и показывает полный знак BULL с расшифровкой.
- Отмена SSH-мастера не меняет активное подключение.

Автоматические проверки используют фиктивные endpoint и временные каталоги.
Реальное подключение, WAN и GPU-конфигурации проверяются отдельно на целевом
оборудовании.
