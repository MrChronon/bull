# Интерфейс BULL v0.24.0.0

При первом показе главного меню BULL рисует полноцветную пиксельную голову быка.
Она выводится один раз за процесс и не повторяется на вложенных экранах. Ресурс
заранее подготовлен из `Assets/Brand/bull-mark-512.png` командой Chafa 1.18.3
`chafa -f symbols -c full -s 30 bull-mark-512.png`, поэтому пользователю не
нужен отдельный `chafa.exe`. Допускаются только безопасные ANSI SGR-коды цвета;
при повреждении ресурса BULL использует встроенный монохромный вариант. Для
корректного отображения нужен Unicode-шрифт Windows Terminal; startup переводит
консоль в UTF-8.

Первый интерактивный экран после логотипа предлагает выбрать **English** или
**Русский**. Выбор сохраняется в `ui_settings.json`, но при следующем запуске его
можно сразу изменить. Перевод относится только к интерфейсу и системным сообщениям:
benchmark prompts, scorers, raw-ответы моделей и сохранённые измерения не меняются.

Тема по умолчанию — **BULL Brand**: primary `#00E6A8`, action `#24D6FF`,
graphite для вторичных пояснений и off-white для основного текста. Прежние темы
Matrix и классическая контрастная доступны в разделе внешнего вида.

Новое: **Тесты → 7. Экспериментальная GPU Lab**, также `/gpu` с главной.
Карты → конфигурации (по одной/вместе) → модели → сценарии → настройки → подтверждение.
Результаты и продолжение находятся внутри того же раздела. Редкие пути к executable
и моделям вынесены в пункт 3 лаборатории. Основная Ollama может быть выключена.
Подробно: `Docs/GPU_LAB.md`. Предыдущие маршруты ниже сохраняются.

## Карта экранов

Главная: 1 Чат; 2 Тесты и результаты; 3 Подключения; 4 Настройки и помощь;
5 Ввести команду; 0 Выйти.

Подключения: 1 этот компьютер; 2 быстрый SSH-алиас; 3 сохранённый сервер;
4 ручная настройка; 5 инструкция по ключам; 6 дополнительные функции.

Вложенное меню: 0 — назад. Мастер SSH: 0 — отменить до сохранения.
Черновик Agent-настроек: S — сохранить, 0 — отменить. Запуск теста — отдельное действие.
Только главная принимает одновременно номер и /команду. В остальных меню вводите
предлагаемые номера; в чате /home вернёт на главную.

| Внешний вид | Значение |
| --- | --- |
| Голубой номер и название | Можно выбрать действие |
| Светлый обычный текст | Информация, не пункт меню |
| Зелёный + OK | Подтверждённый успех |
| Жёлтый + ВНИМАНИЕ | Нужна проверка или нет связи |
| Красный + ОШИБКА | Действие не выполнено |

Настройки → Внешний вид сохраняет яркость темы. Цвет не является единственным сигналом.
Зелёный тонкий разделитель сохраняет Matrix-стиль; бинарные строки и массивные рамки убраны.

## Подключить сервер по существующему алиасу

Если обычная команда `ssh bull-home` уже работает, выберите
**Подключения → Подключиться по SSH-алиасу** и введите `bull-home`. BULL через
`ssh -G` получает адрес, пользователя, порт и первый существующий приватный
`IdentityFile`. Если сетевой host key уже совпадает с OpenSSH `known_hosts`,
повторно переносить fingerprint не нужно. При отсутствии совпадения остаётся
обязательная независимая проверка.

Экран не выполняет `ProxyCommand` и не переносит `ProxyJump`; для таких маршрутов
используйте ручной сценарий. В пункте **Как создать SSH-ключ и алиас** показаны
команды и безопасный пример `~/.ssh/config`. Полная версия — `SSH_QUICKSTART.md`.

## Подключить сервер вручную один раз

Подключения → Настроить сервер вручную. Нужен заранее установленный SSH server и
разрешённый на нём ключ. Введите IP/DNS, внешний SSH-порт, SSH-пользователя и путь
к приватному ключу (не .pub). По умолчанию Ollama на сервере слушает 127.0.0.1:11434.
Если она на другом порту, нажмите A. Не вводите URL вместо IP/DNS.

Мастер показывает публичный ключ узла, полученный из сети. Это не доказательство
подлинности. На сервере выполните показанную команду ssh-keygen и перенесите
fingerprint SHA256:… по доверенному каналу. При несовпадении остановитесь.
Сервер без Ed25519: используйте доверенный Connection JSON через Дополнительно.

На итоговом экране:
1 — сохранить и для следующих версий; 2 — только текущий билд; 0 — отмена.
Проверка связи выполняется сразу; её результат не исчезает до Enter.
При недоступности выбранный сервер не заменяется локальной Ollama.

На следующей версии: Подключения → Выбрать сохранённый сервер → подтвердить.
Первый переход со старого билда: Дополнительно → Перенести из старой версии → папка.
Старый ручной SSH-профиль потребует новой проверки fingerprint.

Мастер не открывает порты, не устанавливает ПО на сервере и не меняет роутер.
Если нет доступа: проверьте VPN/внешний порт, питание сервера, sshd и ключ; затем
Ollama на сервере. Локальная Ollama при этом не нужна. Ключ с паролем должен быть
заранее добавлен в ssh-agent.

## Тесты

Стандартное сравнение: Тесты → Сравнить модели → модели → источник параметров → план.
Свой текст: Тест по своему промпту → новый или сохранённый → модели → настройки.
Агент: Агентская задача → Настройки теста → Выбрать модель → S → запуск → 1.
Полная матрица, CODE, категории, rescore, sweep остаются в Расширенных тестах.
Отчёты и история доступны без backend.

build_test_failure означает неудачную промежуточную проверку кода, не обязательно
падение программы. В Agent-итоге это отдельная строка. Другие события, ручные
вмешательства и сетевые повторы сохраняются отдельно. Одинаковый run_tests после
правки файла не обязательно означает бесполезное повторение.

## Приёмочные сценарии

- Выключить локальную Ollama: главная, команды, подключения, история доступны.
- На главной ввести /bench list; список остаётся до Enter, текст не отправляется модели.
- Настройки → Внешний вид: проверить bright, dim, classic; вернуться без смены backend.
- Отменить мастер SSH на каждом шаге: не появляются активное подключение или запись адресной книги.
- Ввести неверный fingerprint: подключение не сохраняется.
- Создать тестовый прямой alias: быстрый мастер показывает resolved поля, не читает
  ключ и использует доверенный `known_hosts`; option injection и ProxyJump отклоняются.
- Подтвердить валидный сервер, выполнить чат и Agent-тест. Для WAN проверить из другой сети.
- Распаковать другой билд; выбрать сохранённый сервер без ввода полей заново.
- Удалить/переместить ключ: приложение просит новый путь, не создаёт и не копирует ключ.
- Agent: выбрать модель и стандартные настройки; 0 в черновике сохраняет предыдущую конфигурацию.
- По завершении: краткий итог → полные показатели → HTML → назад; сохранённые JSON не перезаписаны.

Автоматические тесты используют фиктивные endpoint и временные папки. Реальную
связь с вашим сервером нужно проверить отдельно — успех unit tests её не подтверждает.

## Принципы

Короткие экраны по задачам, раскрытие редких функций по запросу, явные последствия
действий и различимые статусы опираются на [CLI Guidelines](https://clig.dev/),
[progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)
и [неиспользование одного только цвета](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).
Это не заявление о полной сертификации доступности терминала.
