# Интерфейс BULL v0.29.0.1

[Руководство на русском](ru/USER_GUIDE.md) · [English user guide](en/USER_GUIDE.md)

v0.29 использует терминальный интерфейс. Его задача — провести нового
пользователя от подключения моделей к понятному сравнению без знания внутренних
команд BULL. Графический GUI не входит в этот этап.

## Первый запуск

Перед главным меню BULL показывает стартовый экран с быком в выбранной теме
BULL Red или BULL Matrix, текущей версией и ходом обязательной проверки. Прогресс
обозначает только реально завершённые проверки. При обычном запуске выполняются
18 обязательных проверок целостности, импорта модулей, ресурсов интерфейса,
схем и атомарной записи. Полная регрессия из 668 проверок выполняется при установке,
разработке и сборке через `Run-Tests.ps1`. Ниже этапа видно точное имя проверки,
которое harness вывел непосредственно перед её выполнением. Полоса показывает
фактическое число завершённых проверок и их
общее число, которые harness объявляет сам. Проверки повторяются при каждом запуске,
без использования сохранённого результата. Изображение — локальный версионный
PNG в отдельном desktop-окне. Chafa, внешний просмотрщик и сеть не нужны.
Если Tk недоступен, проверка выполняется в терминале без графического окна.
Начинайте распакованный комплект с `Setup.exe`: язык → тема → наборы/пропуск →
полная регрессия → связь/пропуск → завершение → запуск/выход. `BULL.exe` в корне
появляется только после завершения установки.

После успешной проверки BULL закрывает отдельное окно и продолжает обычный
offline-first запуск. Выбор **English / Русский** появляется только при первом
запуске. Язык сохраняется и позднее меняется в **Настройки программы**. Benchmark prompts, ответы моделей и измерения никогда не переводятся
автоматически.

На каждом следующем экране выводятся полная пиксельная голова быка и расшифровка
названия. Они служат устойчивым визуальным ориентиром, но не заменяют заголовок
и breadcrumb. Переход между страницами очищает предыдущий экран, поэтому меню и
мастера не накладываются друг на друга.
Логотип использует цветные фоновые ячейки с обычными пробелами, а не редкие
символы шрифта. Каждая строка сбрасывает цвет, чтобы фон не переходил в меню.
Без поддержки цвета выводится ASCII-силуэт.
Все 24 строки выводятся и сбрасывают цвет отдельно, название идёт после рисунка.
Правка реализована, но полный рисунок по высоте и одинаковая ширина первого/
повторного запуска требуют проверки в живом терминале; это ещё не закрытая приёмка.

## Главное меню

На первом уровне пять основных разделов и дополнительные инструменты:

Целостность и соединение показаны одним блоком над пунктами меню.
Зелёный означает готовность, жёлтый — предупреждение; состояния не дублируются
под отдельными пунктами. Статус наборов находится в тестировании и настройках
тестов. Их пункты `P` и `7` дают просмотр «набор → задания» без смены выбора.

1. **Тестирование моделей** — запуск, продолжение и результаты.
2. **Чат с моделью** — новый или сохранённый диалог.
3. **Настройки тестов** — установка, импорт, выбор заданий, удаление и мастерская.
4. **Настройки соединения программы** — локальные модели, SSH и параметры движка.
5. **Настройки программы** — язык и цветовые темы.
6. **Дополнительно** — состояние сессии, диагностика, справка и эксперименты.

`0` всегда означает возврат или выход. Опытный пользователь может ввести `/`
команду прямо на главной, но команды не конкурируют с основным сценарием.
Обычный текст модели вводится только в чате.

## Основной сценарий сравнения

**Тестирование моделей → Сравнить по набору тестов**:

1. выбрать точную версию набора и все либо отдельные задания;
2. выбрать установленные модели;
3. оставить стандартные одинаковые условия или явно открыть настройки;
4. проверить план;
5. запустить;
6. прочитать сводку в терминале;
7. открыть рекомендуемый HTML или взять share-safe JSON.

**Тестирование моделей** содержит два прямых действия:

- задача из `UserTests` — повторяемый `.txt` или `.yaml` файл;
- один вставленный prompt — быстрый эксперимент с историей версий.

Стандартный режим использует три seed. Быстрый режим с одним seed подходит для
проверки запуска, но не даёт вывода об устойчивости ранжирования.

## Результат без выхода из BULL

После завершения доступны:

1. краткая сводка в терминале;
2. выбор по собственным приоритетам;
3. полный автономный HTML;
4. пути к файлам для экспорта;
5. raw-ответы моделей;
6. повтор того же теста;
7. другой тест.

Общий терминальный/HTML-отчёт показывает четыре профиля выбора. Для RU/EN
первой идёт отдельная языковая сводка без объединённого победителя:
[метрики и ограничения](ru/RESULTS.md).

Профили общего отчёта:

- **Качество** — приоритет наблюдаемой средней Native quality. При нескольких
  runs нижняя граница 95% CI может отдельно использоваться как консервативная
  величина выбора и всегда подписывается отдельно от среднего балла;
- **Скорость** — приоритет warm tok/s после quality/task gate;
- **Баланс** — совместный учёт качества, скорости, выполнения контракта и VRAM;
- **Мало памяти** — больший вес экономии VRAM после того же gate.

Пункт **Мои приоритеты** принимает веса 0–100 для качества, скорости, выполнения
контракта и VRAM. Сумма нормируется автоматически. Эти значения не меняют score,
не пересчитывают ответы и не создают универсальный рейтинг.

Карта «Native quality ↔ скорость» строится по наблюдаемой средней Native quality
и относительна только моделям текущего прогона.
Правый верхний сектор означает лучшее сочетание двух наблюдаемых показателей;
левый верхний — акцент на качестве; правый нижний — скорость при необходимости
ручной проверки; левый нижний — слабый результат внутри данного набора. При
одинаковой utility нескольких моделей BULL показывает равноценных кандидатов,
а не выбирает модель по её имени. При недостатке сопоставимых метрик BULL не
рисует победителя.

HTML и share-safe evidence предназначены для передачи. Raw JSON может содержать
prompts и ответы, поэтому интерфейс явно помечает его как приватный.

## Пользовательские задачи

В `UserTests` лежат примеры, исключённые из discovery до создания своей копии.
`.txt` отправляется моделям как prompt и не
получает выдуманного quality score. `.yaml` использует только объявленные
детерминированные проверки. Полный контракт, допустимые критерии, правила весов,
critical cap и примеры описаны в `Docs/USER_TESTS.md`.

Ошибочный пользовательский файл не блокирует остальные: BULL показывает имя и
причину отказа. Файлы ограничены по размеру и не могут исполнять Python, shell,
YAML tags, aliases или регулярные выражения.

## Подключение

Обычный экран сгруппирован по месту запуска моделей и содержит:

1. **На этом компьютере** — локальная Ollama на `localhost`;
2. **Удалённый сервер** — выбрать сохранённый сервер;
3. **Удалённый сервер** — добавить его по существующему SSH-алиасу;
4. **Удалённый сервер** — добавить вручную;
5. Импортировать Connection JSON; 6. перенести старую запись;
7. Проверить SSH без inference; 8. инструкция ключа/алиаса; 9. Интернет;
10. Забыть сохранённую запись; 11. параметры движка.

Если `ssh bull-home` уже работает по ключу, достаточно выбрать пункт 3 и ввести
`bull-home`. BULL читает `HostName`, `User`, `Port` и `IdentityFile` через
`ssh -G`, проверяет host key и не копирует приватный ключ. Отдельная SSH-диагностика
выполняется по явному выбору; базовая проверка связи идёт при запуске. Подробнее:
`Docs/SSH_QUICKSTART.md`.

## Дополнительные функции

Раздел **Настройки программы** содержит язык и темы. **Дополнительно** —
плоский список: 1 состояние сессии, 2 диагностика программы и API,
3 как пользоваться BULL, 4 справочник команд, 5 Agent Benchmark.
Диагностика предлагает базовый либо полный внутренний набор проверок.
Результаты находятся в тестировании; параметры движка — в настройках соединения.
Без backend сохранённые данные не выдаются за живые измерения. До начала чата
показывается конфигурация, а не вымышленная активная сессия. GPU Lab удалён;
обычные GPU/VRAM и CPU/RAM показывают измерение либо отдельное N/A с причиной.

## Цвет и доступность

| Отображение | Значение |
| --- | --- |
| Номер и название в цвете темы | Доступное действие |
| Светлый текст | Информация |
| Зелёный + `OK` | Подтверждённый успех |
| Жёлтый + `ВНИМАНИЕ` | Нужна проверка |
| Красный + `ОШИБКА` | Действие не выполнено |

Цвет не является единственным сигналом. Все важные состояния имеют текстовую
подпись. Тема по умолчанию — красная **BULL Red**. В **Настройки программы** доступны
только **BULL Red** и зелёная **BULL Matrix**; там же меняется язык.
BULL Matrix: зелёный бык и акценты, голубые действия; переключение сразу меняет
следующий экран и значки своих ярлыков BULL. Выбор сохраняется независимо от языка.
Прежние названия Matrix остаются совместимыми псевдонимами; высокая контрастность
удалена, её сохранённые настройки переходят на BULL Red.
При следующем запуске BULL Matrix также включает зелёный аналог прежнего
загрузочного рисунка, рамку и полосу прогресса. BULL Red возвращает красный вариант.
Перед первым меню после проверки запуска и при выборе темы заново проверяется
режим цветов терминала и устанавливается UTF-8; устаревший флаг цвета не сохраняется.
Терминальный знак теперь содержит 48×24 ячейки, без повторного масштабирования.
Установка начинается с `Setup.exe`: язык → тема → наборы → регрессия → связь.
Установщик и ярлык запускают один `BULL.exe` в одинаковом профиле Terminal;
для обычной консоли используется Consolas, без изменения глобальных настроек.

## Приёмочные сценарии

- При выключенной Ollama открываются главная, подключение, помощь и результаты.
- Новый пользователь запускает стандартное сравнение без `/bench`-команд.
- Основной сценарий не требует Agent Benchmark; GPU Lab и server/all-in-one setup удалены.
- `.txt` не получает автоматического quality score.
- Неверный `.yaml` изолируется с понятной ошибкой до inference.
- После multi-model прогона терминал показывает профили и двумерную карту.
- Пользовательские веса не меняют сохранённые benchmark scores.
- HTML не содержит raw prompts/answers; raw JSON помечен приватным.
- Английский и русский маршруты не смешивают языки интерфейса.
- Повторный запуск использует сохранённый язык без стартового вопроса.
- Недоступная Ollama не создаёт ложный `OK` и не запускает live telemetry.
- Каждая страница очищает предыдущую и показывает полный знак BULL с расшифровкой.
- Отмена SSH-мастера не меняет активное подключение.

Автоматические проверки используют фиктивные endpoint и временные каталоги.
Реальное подключение, WAN и GPU-конфигурации проверяются отдельно на целевом
оборудовании.
